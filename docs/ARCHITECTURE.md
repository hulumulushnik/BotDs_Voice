# Архитектура

## Слои

```
 Discord Gateway / Interactions
            │
            ▼
┌───────────────────────┐     ┌────────────────────────┐
│ cog.py  (события)     │     │ ui/  (кнопки, модалки) │
│ on_voice_state_update │     │ ControlPanelView       │
│ on_member_update ...  │     │ ActionRunner           │
└──────────┬────────────┘     └───────────┬────────────┘
           │        вызывают              │
           ▼                              ▼
     ┌──────────────────────────────────────────┐
     │ service.py — бизнес-логика               │
     │ проверки прав, антиспам, действия         │──► antispam.py
     │ бросает TriarchError с текстом            │──► permissions.py
     └───────────────────┬──────────────────────┘
                         ▼
     ┌──────────────────────────────────────────┐
     │ repository.py — состояние комнат          │──► data/rooms.json
     └──────────────────────────────────────────┘

 core/audit_log.py — логи в текстовый канал (используют cog и main)
```

Правила зависимостей:

- **cog** и **ui** знают про сервис, но не содержат бизнес-правил: только «принять
  событие → вызвать сервис → показать результат».
- **service** не знает про UI и interaction. Отказ = исключение `TriarchError`
  (`AccessDenied`, `InvalidTarget`, `InvalidInput`, `RateLimited`, `RoomNotFound`),
  текст которого показывается пользователю как есть.
- **repository** не знает про discord.py — хранит только id.

## Данные

`Room` (repository.py):

| Поле | Назначение |
|---|---|
| `channel_id` | id голосового канала |
| `guild_id` | id сервера (лимиты считаются по серверу) |
| `owner_id` | текущий владелец |
| `banned_ids` | забаненные в комнате (для меню разбана) |
| `panel_message_id` | сообщение с панелью — для обновления embed |
| `join_order` | id участников в порядке захода — для автопередачи владения |

После каждого изменения состояние атомарно пишется в `DATA_FILE`
(временный файл + `os.replace`). Повреждённый файл не роняет бота — он стартует с пустым
состоянием и пишет ошибку в лог.

## Потоки

### Создание комнаты

```
Пользователь заходит в триггер-канал (возможно, из своей комнаты)
 ├─ cog._handle_leave(старая комната)      ← выход обрабатывается ПЕРВЫМ
 │    └─ удалить, если пуста / иначе передать следующему по join_order
 └─ cog._handle_join
     └─ service.create_room
         ├─ роль «Заглушён» / «Не верифицирован»  → AccessDenied
         ├─ создание уже идёт                      → игнор
         ├─ кулдаун                                → RateLimited
         ├─ лимит комнат на сервере                → AccessDenied
         └─ create_voice_channel + register_room
     ├─ ошибка → cog._deny: отключить, написать в ЛС, лог
     └─ move_to(комната) → send_panel → лог
```

### Нажатие кнопки панели

```
Button.callback
 └─ ActionRunner.run(interaction, handler)
     ├─ service.require_room(interaction.channel)   → RoomNotFound
     ├─ service.check_panel_rate(user)              → RateLimited
     ├─ service.require_manager(...)                → AccessDenied
     └─ handler(...)  → service.<действие>
 ловит TriarchError / discord.Forbidden / HTTPException → эфемерный ответ
```

Модальные окна и меню выбора участника тоже проходят через `ActionRunner.run`,
поэтому права проверяются заново в момент отправки, а не только при открытии.

### Мут / бан (переключатели)

Одна кнопка — два действия. Сервис смотрит текущее состояние выбранного участника:

- `toggle_mute`: в overwrite участника `speak = False` → размут, иначе мут
  (мутить можно только тех, кто в комнате);
- `toggle_ban`: участник в `banned_ids` → разбан, иначе бан.

Метод возвращает новое состояние, UI по нему выбирает текст ответа.

### Мгновенный мут (серверный мут под контролем бота)

Discord применяет запрет `speak` в overwrite только при новом подключении, поэтому мут
состоит из двух частей:

1. **overwrite `speak=False`** в комнате — постоянный: действует при перезаходе;
2. **серверный мут** (`member.edit(mute=True)`) — мгновенный.

Серверный мут действует на весь сервер, поэтому бот ведёт учёт выданных им мутов
(`repository._server_muted`, сохраняется в `DATA_FILE`) и вызывает
`service.sync_server_mute(member)` при каждом переходе между каналами:

| Где участник | Действие |
|---|---|
| в комнате, где у него `speak=False` | включить серверный мут, если не включён, и запомнить |
| в любом другом канале, мут выдан ботом | снять и забыть |
| в любом другом канале, мут выдан модератором | ничего |
| не в голосе | ничего (Discord не даёт менять мут) — снимется при следующем подключении |

Фоновый цикл раз в `CLEANUP_INTERVAL` повторяет синхронизацию для всех запомненных
участников — на случай пропущенных событий или перезапуска бота.

### Подъём комнаты наверх

`service.raise_room` → `channel.move(after=триггер)`, если триггер в той же категории,
иначе `channel.move(beginning=True)`. Кулдаун на комнату — `RAISE_COOLDOWN`.

### Передача владения

- **Вручную (👑):** меню выбора строится из `service.transfer_candidates()` — только
  люди, которые сейчас в комнате; `transfer_ownership` дополнительно проверяет это
  в момент выбора.
- **Автоматически:** при выходе участника `cog._handle_leave` вызывает
  `service.reassign_if_owner_absent`. Если владельца в комнате нет, новым становится
  первый по `join_order` из оставшихся, кто может владеть комнатой. Панель обновляется,
  в чат комнаты и в лог уходит сообщение. Та же проверка выполняется в фоновом цикле —
  на случай пропущенных событий (например, перезапуск бота).

При любой смене владельца у старого снимаются права владельца на канал.

### Удаление комнат

Две независимые линии:

1. **Сразу:** `on_voice_state_update` → `service.delete_if_empty` (с паузой 1 с, чтобы
   Discord обновил список участников).
2. **Фоново:** `cleanup_loop` каждые `CLEANUP_INTERVAL` секунд — удаляет пустые комнаты
   и забывает каналы, которых больше нет (например, удалённые, пока бот был выключен).

### Перезапуск

- Комнаты загружаются из `DATA_FILE`.
- `ControlPanelView` зарегистрирован через `bot.add_view()` и определяет комнату по
  `interaction.channel`, поэтому кнопки старых панелей продолжают работать.
- При первом `on_ready` все сохранённые панели перерисовываются под текущую раскладку
  кнопок (`refresh_panel(..., view=...)`) — после изменения `PANEL_GRID` старые панели
  обновятся сами.
- Первая итерация `cleanup_loop` после `wait_until_ready()` убирает всё, что опустело
  за время простоя.

## Как добавить кнопку

1. Добавьте `PanelButton("key", "эмодзи", "Описание", стиль)` в нужный ряд
   `PANEL_GRID` (`ui/layout.py`). Максимум 5 кнопок в ряду и 5 рядов.
   Описание автоматически появится в легенде панели.
2. Реализуйте логику в `TriarchService` (бросайте `TriarchError` при отказе).
3. Добавьте обработчик в словарь `handlers` в `ControlPanelView.__init__`.
   Если обработчика нет — бот не запустится (`RuntimeError`), а не упадёт на нажатии.
4. Для действия «выбрать участника» оберните его в
   `self._select(MemberAction("Вопрос?", функция))`, где функция возвращает
   пару текстов `(ответ инициатору, сообщение в комнату)`.

`custom_id` кнопки = `triarch:panel:<key>`. Не меняйте `key` у существующих кнопок —
иначе уже опубликованные панели перестанут работать.
